GATE CSE Operating Systems Formula Sheet: Paging, EAT, Deadlock

By MD ANISH AHAMADUpdated 4 Oct 20268 min read

Operating systems numerical questions in GATE CSE come from a short list of formulas: scheduling times, effective access time, paging arithmetic, deadlock counts, inode sizes and fork counts. This sheet goes deeper than the general GATE CSE formula sheet. Each formula comes with a one-line worked example and the trap that costs marks.

Key takeaways

  • Scheduling questions use three subtractions: turnaround is completion minus arrival, waiting is turnaround minus burst, and response is first dispatch minus arrival.
  • The TLB formula charges a miss one memory access per page-table level plus the data access, so a two-level table costs 3tm3t_m3tm​ on a miss.
  • Demand-paging effective access time is dominated by the fault term, so convert milliseconds to nanoseconds before you multiply.
  • Deadlock is impossible only with n(k−1)+1n(k - 1) + 1n(k−1)+1 units; n(k−1)n(k - 1)n(k−1) units can still deadlock.
  • An inode's double indirect pointer reaches p2p^2p2 blocks, never 2p2p2p.
  • Most operating systems marks lost in revision come from units and conventions, not from the formulas themselves.

The terms this sheet uses

Every formula below is built from a few quantities. Learn them once and the formulas read like sentences.

  • Arrival time (AAA) is when a process enters the ready queue. Burst time is the CPU time it needs. Completion time (CCC) is when it finishes.
  • A page is a fixed-size block of virtual memory, and a frame is a block of physical memory of the same size. The offset is the part of an address that selects a byte inside a page, so offset bits o=log⁡2(page size)o = \log_2(\text{page size})o=log2​(page size).
  • A page-table entry (PTE) holds a frame number plus flag bits. The TLB is a small cache of recent translations, and the hit ratio hhh is the fraction of lookups it answers.
  • The page-fault rate ppp is the fraction of memory references whose page is not in memory.
  • An inode stores a file's block pointers: ddd direct pointers and one single, one double and one triple indirect pointer.

Logs are base 2 throughout, and KB means 2102^{10}210 bytes unless a question says otherwise.

Scheduling formulas, from timeline to averages

Every scheduling question ends in the same three subtractions. Draw the Gantt chart first, read off completion times, then apply the table.

Two conventions decide many timelines. In round robin, a new arrival joins the queue before the preempted process when both happen at the same instant. In SRTF, a new arrival preempts only if its burst is strictly less than the running process's remaining time.

Trap: A quantum larger than every remaining burst turns round robin into FCFS. Count context switches only when the running process changes. The CPU scheduling question guide works through these timelines.

Effective access time with a TLB

The average time is the hit case weighted by its probability, plus the miss case weighted by its own. On a hit you pay one TLB lookup and one memory access. On a miss you pay the lookup, one access per page-table level, and then the data access:

EAT=h (tTLB+tm)+(1−h) (tTLB+(L+1) tm)\text{EAT} = h\,(t_{TLB} + t_{m}) + (1 - h)\,\big(t_{TLB} + (L + 1)\,t_{m}\big)EAT=h(tTLB​+tm​)+(1−h)(tTLB​+(L+1)tm​)

Here hhh is the TLB hit ratio, tTLBt_{TLB}tTLB​ the lookup time, tmt_mtm​ one memory access and LLL the number of page-table levels.

Worked example. Take tTLB=10t_{TLB} = 10tTLB​=10 ns, tm=100t_m = 100tm​=100 ns, h=0.9h = 0.9h=0.9 and a single-level table:

EAT=0.9×110+0.1×210=99+21=120 ns\text{EAT} = 0.9 \times 110 + 0.1 \times 210 = 99 + 21 = 120\text{ ns}EAT=0.9×110+0.1×210=99+21=120 ns

With a two-level table the miss term grows to 10+300=31010 + 300 = 31010+300=310 ns, so the EAT becomes 99+31=13099 + 31 = 13099+31=130 ns.

If the question says the TLB is searched in parallel with memory, the hit term is just tmt_mtm​ and the miss term stays tTLB+(L+1) tmt_{TLB} + (L + 1)\,t_mtTLB​+(L+1)tm​. The page-table walk always goes to memory.

Effective access time with page faults

Demand paging uses the same weighting, with the page-fault rate ppp in place of the miss ratio:

EAT=(1−p) tm+p tfault,tfault=d tdirty+(1−d) tclean\text{EAT} = (1 - p)\,t_{m} + p\,t_{\text{fault}}, \qquad t_{\text{fault}} = d\,t_{\text{dirty}} + (1 - d)\,t_{\text{clean}}EAT=(1−p)tm​+ptfault​,tfault​=dtdirty​+(1−d)tclean​

Here ddd is the fraction of victim pages that are dirty and must be written back.

Worked example. With tm=100t_m = 100tm​=100 ns, tfault=8t_{\text{fault}} = 8tfault​=8 ms =8×106= 8 \times 10^{6}=8×106 ns and p=10−6p = 10^{-6}p=10−6, the fault term adds 10−6×8×106=810^{-6} \times 8 \times 10^{6} = 810−6×8×106=8 ns. The EAT is about 100+8=108100 + 8 = 108100+8=108 ns.

Trap: Multiplying ppp by 8 instead of 8×1068 \times 10^{6}8×106 gives an answer a million times too small. Write the unit next to every number before you substitute.

Deadlock: the minimum number of resources

The worst case for one resource type is that every process holds one unit fewer than it needs. If one more unit exists, some process can finish and release everything. So deadlock is impossible exactly when:

R≥∑i(needi−1)+1R \ge \sum_{i} (\text{need}_i - 1) + 1R≥i∑​(needi​−1)+1

Max file size=(d+p+p2+p3)×B\text{Max file size} = (d + p + p^{2} + p^{3}) \times BMax file size=(d+p+p2+p3)×B

Frequently asked questions

What is the effective access time formula with a TLB in GATE?

With a serial TLB lookup and an L-level page table, EAT =h(tTLB+tm)+(1−h)(tTLB+(L+1)tm)= h(t_{TLB} + t_m) + (1 - h)(t_{TLB} + (L + 1)t_m)=h(tTLB​+tm​)+(1−h)(tTLB​+(L+1)tm​). A hit costs one TLB lookup and one memory access. A miss costs the lookup, L page-table accesses and the data access. For a single-level table the miss term is tTLB+2tmt_{TLB} + 2t_mtTLB​+2tm​. Read whether the question says the TLB lookup overlaps memory access.

How many resources are needed so that deadlock can never occur?

For one resource type, deadlock is impossible when the number of units R is at least the sum of (need minus one) over all processes, plus one. With n processes each needing k units this becomes n(k−1)+1n(k - 1) + 1n(k−1)+1. Exactly n(k−1)n(k - 1)n(k−1) units is still deadlock-prone, because every process can hold k−1k - 1k−1 units and wait forever.

How do I find the number of levels in a multi-level page table?

First find how many entries fit in one page: page size divided by the page-table entry size. The bits per level are the base-2 log of that number. Divide the page-number bits by the bits per level and take the ceiling. For example, 8 KB pages with 8-byte entries give 1,024 entries, so 10 bits per level, and 33 page-number bits need 4 levels.

What is the maximum file size formula for an inode?

Maximum file size =(d+p+p2+p3)×B= (d + p + p^2 + p^3) \times B=(d+p+p2+p3)×B, where d is the number of direct pointers, B is the block size and p is the number of pointers that fit in one block, block size divided by pointer size. The double indirect pointer reaches p2p^2p2 blocks and the triple indirect p3p^3p3. Units are powers of two unless the question says otherwise.

Do I need to memorise operating system formulas for GATE CSE?

Yes. You cannot carry notes into the exam hall, and most operating system numerical questions in past papers reuse a small set of formulas: scheduling times, effective access time, paging levels, minimum resources for deadlock freedom and inode file size. Learn each with one worked example and its trap. Confirm the current exam-day rules at gate2027.iitm.ac.in.
