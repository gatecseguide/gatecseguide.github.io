Key takeaways

  • The Master theorem compares f(n)f(n)f(n) with nlog⁡ban^{\log_b a}nlogb​a; Case 3 also needs the regularity condition.
  • Merge sort is stable but not in place; quicksort and heapsort are in place but not stable.
  • Linear probing degrades much faster than chaining as the load factor α\alphaα approaches 1.
  • Build-heap is Θ(n)\Theta(n)Θ(n), not Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn), because most nodes sit near the bottom.
  • Graph algorithm complexity depends on the data structure: an array suits dense graphs, a heap suits sparse ones.
  • Catalan numbers count BSTs, binary tree shapes and stack permutations; KnK_nKn​ has nn−2n^{n-2}nn−2 spanning trees.

The terms this sheet uses

  • nnn is the input size. For graphs, VVV is the number of vertices and EEE the number of edges.
  • The load factor α=n/m\alpha = n/mα=n/m is the number of keys nnn stored in a hash table of mmm slots.
  • A probe is one slot examined during a hash search or insertion.
  • A sort is stable if equal keys keep their input order, and in place if it uses only O(1)O(1)O(1) extra space beyond the input.
  • Heap height counts edges, so a single node has height 0.

Logs are base 2 unless a base is written.

Recursion trees and the recurrences worth memorising

When the split is unequal, add the cost level by level instead. If the level sums shrink geometrically, the top level dominates. If they stay equal, multiply one level by the depth. If they grow, the leaves dominate.

Worked example. For T(n)=T(n/2)+T(n/4)+nT(n) = T(n/2) + T(n/4) + nT(n)=T(n/2)+T(n/4)+n, the level sums are nnn, 34n\displaystyle \tfrac{3}{4}n43​n, 916n\displaystyle \tfrac{9}{16}n169​n, and so on:

∑i≥0(34)in=n1−3/4=4n⇒T(n)=Θ(n)\sum_{i \ge 0} \left(\tfrac{3}{4}\right)^{i} n = \frac{n}{1 - 3/4} = 4n \quad\Rightarrow\quad T(n) = \Theta(n)i≥0∑​(43​)in=1−3/4n​=4n⇒T(n)=Θ(n)

Insertion sort makes inversions +(n−1)+ (n - 1)+(n−1) comparisons, minus one for each key that moves to the front. Selection sort always makes n(n−1)/2n(n-1)/2n(n−1)/2 comparisons and at most n−1n - 1n−1 swaps. Any comparison sort needs ⌈log⁡2n!⌉\lceil \log_2 n! \rceil⌈log2​n!⌉ comparisons in the worst case.

Worked example. Insertion sort on [3,1,2,5,4][3, 1, 2, 5, 4][3,1,2,5,4]. The inversions are (3,1)(3,1)(3,1), (3,2)(3,2)(3,2) and (5,4)(5,4)(5,4), so there are 3. Only the key 1 moves to the front. The count is 3+4−1=63 + 4 - 1 = 63+4−1=6 comparisons. The comparison lower bound, ⌈log⁡2120⌉=7\lceil \log_2 120 \rceil = 7⌈log2​120⌉=7, applies to the worst input, not this one.

The trap: quicksort with a first-element pivot hits its Θ(n2)\Theta(n^{2})Θ(n2) worst case on already sorted input.

Which sorting algorithms are stable and which are in place?

Insertion, bubble, merge, counting and radix sort are stable. Insertion, bubble, selection, heapsort and quicksort are in place, with quicksort using only its recursion stack. What is the time complexity of Dijkstra's algorithm?

It depends on the priority queue.
